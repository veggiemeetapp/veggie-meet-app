# Environment Configuration Checklist (Production)

The production project must ship with **only** the following runtime env
vars in the client `.env`. All values are auto-generated by Lovable
Cloud when the fresh project is created — no manual editing.

| Variable | Required | Public? | Client-safe? | Where configured | How to verify |
|---|---|---|---|---|---|
| `VITE_SUPABASE_URL` | Yes | Yes | Yes | Auto in `.env` on Cloud project creation | `grep VITE_SUPABASE_URL .env` matches new project |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Yes | Yes | Yes | Auto in `.env` | Starts with `sb_publishable_` |
| `VITE_SUPABASE_PROJECT_ID` | Yes | Yes | Yes | Auto in `.env` | Matches new production project id |

## Must NOT appear anywhere (source, `.env`, `dist/`)

- `SUPABASE_SERVICE_ROLE_KEY` (any form)
- `service_role` bearer JWTs
- Preview backend URL (`zllamljlygjkknsguuki`)
- Preview publishable key (`sb_publishable_8GBBSf4Dcm1n49Akt7dHSw_r3WDPgAH`)
- Hardcoded `http://localhost` URLs in shipped code
- Debug / QA flags (e.g. `VITE_QA=`, `VITE_DEBUG=`)
- Source-map data URLs in `dist/*.js`
- Any password, cookie, bearer token, or private key

## Verification scans

Run these against the production project's checkout **before** building:

```bash
# Preview references
grep -rIn "zllamljlygjkknsguuki" src/ index.html .env dist/ 2>/dev/null | grep -v Binary
grep -rIn "sb_publishable_8GBBSf4Dcm1n49Akt7dHSw" src/ index.html .env dist/ 2>/dev/null | grep -v Binary

# Service-role key
grep -rIn "SUPABASE_SERVICE_ROLE\|sb_secret_\|service_role" src/ dist/ 2>/dev/null | grep -v Binary

# QA / debug flags
grep -rIn "VITE_QA\|VITE_DEBUG\|__QA__" src/ .env dist/ 2>/dev/null | grep -v Binary
```

All four scans must return zero matches. `verify_production_build.sh`
enforces this and exits nonzero on any hit.
